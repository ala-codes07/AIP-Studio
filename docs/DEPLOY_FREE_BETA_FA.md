# AIP Studio — استقرار نسخه آزمایشی آنلاین با سرویس‌های رایگان

این راهنما برای **نسخه آزمایشی محدود ۳ تا ۵ نفر** است، نه سرویس تجاری با SLA.

## سرویس‌ها

- **GitHub:** مخزن سورس، بدون فایل `.env` یا دیتابیس
- **Neon Free:** دیتابیس PostgreSQL پایدار بین ری‌استارت‌ها؛ سقف استفاده رایگان دارد — https://neon.tech/
- **Brevo Free:** ارسال ایمیل تأیید و فراموشی رمز از طریق HTTPS، نه SMTP — https://www.brevo.com/
- **Render Free:** وب‌اپ با آدرس HTTPS اختصاصی `*.onrender.com` — https://dashboard.render.com/

Render Free بعد از ۱۵ دقیقه بی‌درخواستی می‌خوابد، هنگام بیدارشدن تأخیر دارد، فضای دیسک موقتی است، و SMTP روی پورت‌های ۲۵/۴۶۵/۵۸۷ را مسدود می‌کند. **از Render Postgres Free استفاده نکنید:** دیتابیس رایگان آن پس از ۳۰ روز منقضی می‌شود. Neon را جداگانه انتخاب کرده‌ایم. Worker در یک ترد داخل همین سرویس اجرا می‌شود و با خواب سرویس متوقف می‌شود؛ بعد از برگشت سرویس دوباره شروع می‌شود. اسکن‌های نیمه‌کاره ممکن است نیاز به ارسال مجدد داشته باشند.

### ۱. فایل‌های محلی را نگه دارید و مخزن را منتشر کنید

در پوشه `AIP-Studio-Final`، اصلاحیه آنلاین را اعمال کنید. فایل `.env` و دیتابیس محلی **نباید** وارد GitHub شوند.

برای بررسی قبل از Commit:

```powershell
cd "C:\Users\2024\autonomous-intelligence-platform-professional\AIP-Studio-Final"
git status --short
git check-ignore -v .env backend/platform.db backend/.venv/
```

حتماً **Git repository visibility** و فایل‌های ردیابی‌شده را پیش از انتشار بررسی کنید. اطلاعات اسکن‌شده و فایل CSV واقعی Search Console را داخل مخزن نگذارید.

### ۲. Neon — دیتابیس

1. در https://console.neon.tech/ یک پروژه PostgreSQL رایگان ایجاد کنید.
2. روی **Connect** کلیک کنید و Connection string را کپی کنید (ترجیحاً pooled URL برای اتصال‌های کم‌مصرف).
3. آدرس را بعداً در Render به عنوان `DATABASE_URL` وارد کنید؛ **در `.env.example` و GitHub کپی نکنید**.
4. `sslmode=require` و اگر ارائه شده `channel_binding=require` را حفظ کنید. پروژه هر دو فرمت `postgresql://` و `postgresql+psycopg://` را می‌پذیرد.

این دیتابیس **جدید و جدا از SQLite لپ‌تاپ** است؛ حساب فعلی به صورت خودکار به آن منتقل نمی‌شود. برای نسخه آزمایشی، مجدداً ثبت‌نام کنید. دیتابیس اصلی را حذف نکنید.

### ۳. Brevo — ارسال رایگان ایمیل از طریق API

1. در https://app.brevo.com/ ثبت‌نام کنید و قابلیت ارسال transactional email را فعال کنید.
2. یک **Sender** بسازید و آدرس آن را تأیید کنید؛ وضعیت تأیید و محدودیت حساب را بررسی کنید.
3. از بخش SMTP & API، یک **API key** جدید بگیرید.
4. در تنظیمات Render مقدار `EMAIL_MODE=brevo`، `BREVO_API_KEY` و `SMTP_FROM` (همان آدرس فرستنده تأییدشده) را وارد کنید.

توجه: استفاده از فرستنده `@gmail.com` ممکن است باعث شود Brevo آدرس فرستنده را بازنویسی کند یا به دلیل الزامات احراز هویت دامنه، تحویل ایمیل محدود شود. برای یک ارسال عمومی حرفه‌ای، دامنه اختصاصی و احراز هویت SPF/DKIM/DMARC توصیه می‌شود. Gmail App Password **در Render Free کار نمی‌کند** چون پورت SMTP بسته است. هیچ‌وقت API key یا App Password را به دیگران ندهید.

### ۴. Render — سرویس وب رایگان

1. بعد از Push کردن مخزن، وارد https://dashboard.render.com/ شوید.
2. **New → Blueprint** را انتخاب کنید و مخزن GitHub خود را متصل کنید.
3. Render فایل `render.yaml` ریشه مخزن را تشخیص می‌دهد. سرویس `aip-studio-beta` با پلن **Free** ایجاد می‌شود.
4. مقادیر مخفی را **داخل داشبورد Render** تعیین کنید:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Connection string محرمانه Neon |
| `BREVO_API_KEY` | API key محرمانه Brevo |
| `SMTP_FROM` | ایمیل Sender تأییدشده در Brevo |
| `BETA_ALLOWED_EMAILS` | آدرس‌های دعوت‌شده با `,` انگلیسی جدا شوند؛ ابتدا فقط ایمیل خودتان |
| `SECRET_KEY` | توسط Render تصادفی تولید می‌شود؛ مقدار آن را عمومی نکنید |

5. Deploy را شروع کنید و **Logs** را بررسی کنید. اجرای `start_cloud` ابتدا Alembic migrations را اعمال می‌کند، بعد Uvicorn **با یک پردازش** بالا می‌آید. اگر دیتابیس/ایمیل تنظیم نباشد، سرویس عمداً راه‌اندازی نمی‌شود.
6. لینک HTTPS اختصاصی `https://...onrender.com` را باز کنید؛ قسمت `/api/v1/health/ready` باید `status=ready` بدهد.

### ۵. آزمون روی محیط آنلاین

- با **ایمیل دعوت‌شده** ثبت‌نام کنید. ثبت‌نام با ایمیل غیرمجاز باید `403` شود.
- کد تأیید را از طریق Brevo دریافت کنید؛ بازیابی رمز و ورود مجدد را امتحان کنید.
- **یک** سایت عمومی که اجازه بررسی آن را دارید ثبت کنید و Scan بزنید؛ وضعیت Job از `queued` به `running` و سپس `completed/failed` تغییر کند. سایت‌هایی که `robots.txt` خزیدن را ممنوع کرده‌اند نباید پیمایش شوند.
- فایل Queries CSV آزمایشی و سپس یک فایل واقعیِ غیرحساس را وارد کنید.
- در Render پس از بازشدن دوباره سرویس وضعیت پایگاه داده و حساب را بررسی کنید. ممکن است بعد از خواب سرویس، اولین درخواست تا حدود یک دقیقه طول بکشد.

### محدودیت‌ها و خطوط قرمز

- این استقرار برای **دعوت محدود** است؛ ثبت‌نام عمومی آزاد، ضدربات، نظارت امنیتی حرفه‌ای و صف مستقل مقیاس‌پذیر هنوز آماده نیست.
- Ollama روی Render Free نصب/اجرا نمی‌شود. `LLM_PROVIDER=local` یعنی پیشنهادهای **قانون‌محور**، نه اجرای مدل زبانی مولد. از عنوان «مدل AI محلی در کلاد» استفاده نکنید.
- هیچ سرویس رایگانی پایداری ۲۴/۷، پرداخت صفر در تمام شرایط یا کیفیت ایمیل را تضمین نمی‌کند. محدودیت‌های هزینه/حجم را داخل داشبورد ارائه‌دهنده بررسی کنید.
- در بازبینی عمومی GitHub، فایل‌های `.env`، `.db`، `*.log`، توکن‌ها، کلیدهای ایمیل و فایل خام Search Console را منتشر نکنید.
- برای نسخه تجاری، Worker مستقل، محدودکننده نرخ در لبه، مانیتورینگ، بکاپ دیتابیس، سقف تعداد کاربران و دامنه/ایمیل اختصاصی توصیه می‌شود.
